# Requirements: SIP Messaging

> Spec-Driven Development flow for Message class and messaging operations.

## Overview

Messaging provides SIP instant messaging (IM) and typing indicator functionality. Message is a passive data wrapper with no behavior.

---

## Functional Requirements

### FR-1: Message Data Representation

**Description**: Message class SHALL represent SIP MESSAGE requests.

**Requirements**:
- FR-1.1: Message SHALL provide `getAccountId()` returning account ID
- FR-1.2: Message SHALL provide `getContactUri()` returning sender's Contact URI
- FR-1.3: Message SHALL provide `getFromUri()` returning sender URI
- FR-1.4: Message SHALL provide `getFromName()` returning sender name (or null)
- FR-1.5: Message SHALL provide `getFromNumber()` returning sender number
- FR-1.6: Message SHALL provide `getToUri()` returning destination URI
- FR-1.7: Message SHALL provide `getBody()` returning message body
- FR-1.8: Message SHALL provide `getContentType()` returning MIME type

**Source**: src/Message.js

---

### FR-2: URI Parsing

**Description**: Message SHALL parse From URI to extract name and number.

**Requirements**:
- FR-2.1: Message SHALL extract name from `"Name" <sip:number @domain>` format
- FR-2.2: Message SHALL extract number from `sip:number @domain` format
- FR-2.3: Message SHALL return null if name not present
- FR-2.4: Message SHALL return null if parsing fails

**Source**: Message constructor

---

### FR-3: Send Message

**Description**: Endpoint SHALL provide message sending capability.

**Requirements**:
- FR-3.1: Endpoint SHALL provide `sendMessage(account, destination, msg)`
- FR-3.2: `sendMessage()` SHALL normalize destination URI
- FR-3.3: `sendMessage()` SHALL return Promise
- FR-3.4: `sendMessage()` SHALL resolve on success
- FR-3.5: `sendMessage()` SHALL reject on failure

**Source**: Endpoint.sendMessage()

---

### FR-4: Typing Indicators

**Description**: Endpoint SHALL provide typing notification capability.

**Requirements**:
- FR-4.1: Endpoint SHALL provide `imTyping(account, destination, isTyping)`
- FR-4.2: `imTyping()` SHALL normalize destination URI
- FR-4.3: `imTyping()` SHALL return Promise
- FR-4.4: `isTyping` parameter SHALL be boolean
- FR-4.5: `imTyping()` SHALL resolve on success
- FR-4.6: `imTyping()` SHALL reject on failure

**Source**: Endpoint.imTyping()

---

### FR-5: Message Reception

**Description**: Endpoint SHALL emit events for incoming messages.

**Requirements**:
- FR-5.1: Endpoint SHALL emit `message_received` event
- FR-5.2: Event payload SHALL be Message instance
- FR-5.3: Message SHALL be created from native data

**Source**: Endpoint._onMessageReceived()

## Non-Functional Requirements

### NFR-1: Performance

- NFR-1.1: Message object creation SHALL complete in < 1ms
- NFR-1.2: sendMessage() latency SHALL be < 500ms (network dependent)

### NFR-2: Compatibility

- NFR-2.1: SHALL support RFC 3428 (SIP IM)
- NFR-2.2: SHALL support text/plain content type
- NFR-2.3: SHALL support other MIME types as provided by native

## Constraints

- C-1: Message is immutable snapshot
- C-2: No message history or threading
- C-3: No delivery confirmation (fire-and-forget)
- C-4: Depends on native PjSIP MESSAGE support
