# Requirements: Event System

> Spec-Driven Development flow for event routing and emission architecture.

## Overview

The event system provides bidirectional event routing between native PjSIP module and application code using React Native's DeviceEventEmitter and Node.js EventEmitter.

---

## Functional Requirements

### FR-1: Event Subscription

**Description**: Endpoint SHALL subscribe to native events on construction.

**Requirements**:
- FR-1.1: Endpoint constructor SHALL call `DeviceEventEmitter.addListener()` 7 times
- FR-1.2: Endpoint SHALL subscribe to `pjSipRegistrationChanged`
- FR-1.3: Endpoint SHALL subscribe to `pjSipCallReceived`
- FR-1.4: Endpoint SHALL subscribe to `pjSipCallChanged`
- FR-1.5: Endpoint SHALL subscribe to `pjSipCallTerminated`
- FR-1.6: Endpoint SHALL subscribe to `pjSipCallScreenLocked`
- FR-1.7: Endpoint SHALL subscribe to `pjSipMessageReceived`
- FR-1.8: Endpoint SHALL subscribe to `pjSipConnectivityChanged`
- FR-1.9: All listeners SHALL be bound to `this` context

**Source**: Endpoint constructor

---

### FR-2: Event Translation

**Description**: Endpoint SHALL translate native events to public API events.

**Requirements**:
- FR-2.1: `_onRegistrationChanged(data)` SHALL emit `registration_changed` with Account
- FR-2.2: `_onCallReceived(data)` SHALL emit `call_received` with Call
- FR-2.3: `_onCallChanged(data)` SHALL emit `call_changed` with Call
- FR-2.4: `_onCallTerminated(data)` SHALL emit `call_terminated` with Call
- FR-2.5: `_onCallScreenLocked(lock)` SHALL emit `call_screen_locked` with boolean
- FR-2.6: `_onMessageReceived(data)` SHALL emit `message_received` with Message
- FR-2.7: `_onConnectivityChanged(available)` SHALL emit `connectivity_changed`

**Source**: Endpoint private event handlers

---

### FR-3: Event Emission

**Description**: Endpoint SHALL extend EventEmitter for public API.

**Requirements**:
- FR-3.1: Endpoint SHALL extend Node.js EventEmitter
- FR-3.2: Endpoint SHALL inherit EventEmitter methods
- FR-3.3: Application SHALL use `endpoint.on(event, callback)` for listening
- FR-3.4: Application SHALL use `endpoint.emit(event, data)` internally

**Source**: Endpoint class declaration

---

### FR-4: Data Transformation

**Description**: Event handlers SHALL transform native data to class instances.

**Requirements**:
- FR-4.1: Registration events SHALL create new Account(data)
- FR-4.2: Call events SHALL create new Call(data)
- FR-4.3: Message events SHALL create new Message(data)
- FR-4.4: Screen lock event SHALL pass boolean unchanged
- FR-4.5: Connectivity event SHALL pass data unchanged

**Source**: Event handler implementations

## Non-Functional Requirements

### NFR-1: Performance

- NFR-1.1: Event emission SHALL be synchronous (< 1ms)
- NFR-1.2: Event handler execution SHALL complete in < 10ms
- NFR-1.3: No blocking operations in event handlers

### NFR-2: Memory

- NFR-2.1: Event listeners SHALL be held in memory for application lifetime
- NFR-2.2: No memory leaks from event listener accumulation

### NFR-3: Reliability

- NFR-3.1: Events SHALL NOT be dropped under normal conditions
- NFR-3.2: Event order SHALL be preserved (FIFO)

---

## Constraints

- C-1: Event listeners are never removed (memory leak risk)
- C-2: No error event channel (errors only via Promise rejections)
- C-3: No event filtering or throttling
- C-4: Event handlers are private (naming convention)

## Dependencies

- React Native DeviceEventEmitter (native events)
- Node.js EventEmitter (public API)
- Account, Call, Message classes (data transformation)
